## Purpose

Define durable complete inquiry artifacts, concise Jasper presentation, bounded playback, revision and storage boundaries, and compatibility with current presentation and persistence systems.

## ADDED Requirements

### Requirement: The complete artifact is distinct from the summary

The canonical inquiry artifact MUST preserve the full bucket and tent-pole history, branch tree, questions, evidence/report references, claims, framework metadata, user confirmations, revisions, limitations, provenance, and authorization state. Jasper summaries SHOULD be concise and MUST link to the relevant complete artifact portions rather than replacing them.

#### Scenario: A user inspects the board

- **WHEN** a user opens an inquiry board
- **THEN** the board MUST provide the complete available artifact and visibly distinguish user-authored, user-confirmed, proposed, inferred, observed, and externally sourced material

#### Scenario: A summary is displayed

- **WHEN** Jasper summarizes a research pass or branch
- **THEN** the summary MUST identify its scope and attribution and MUST leave the complete artifact available for review

### Requirement: Playback is bounded and provenance-preserving

Playback MUST be limited by an explicit user-selected segment, item range, or time/length bound. It MUST identify whether each segment is a summary, source excerpt, user-authored content, or other attributed artifact and MUST support pause, stop, and revisit.

#### Scenario: A long inquiry is replayed

- **WHEN** a user requests playback of a large inquiry
- **THEN** the system MUST offer or apply a bounded segment and MUST NOT silently play the entire history or claim that a summary is the original record

### Requirement: Session and memory boundaries are explicit

Durable records MUST be associated with the producing session/thread and revision identity, following `anatomy-of-a-session` and `durable-interaction-records`. Checkpoints MUST remain bounded working state; the established Store/evidence boundary MUST remain authoritative; PostgreSQL/session catalog MUST remain a rebuildable projection. Cross-session memory reuse MUST be opt-in, owner-authorized, provenance-linked, and revocable.

#### Scenario: A session is reopened

- **WHEN** a user reopens an inquiry session after a restart
- **THEN** the system MUST reconstruct the latest valid artifact and revision links without treating a projection or transient checkpoint as the sole source of truth

#### Scenario: Cross-session memory is not authorized

- **WHEN** an inquiry could use material from another session without explicit permission
- **THEN** the system MUST not use or expose that material

### Requirement: Proposed and confirmed structures remain separate

Board nodes, branches, framework mappings, and tent poles generated by the system MUST carry proposed status until explicit user confirmation. User edits MUST create revisions and MUST NOT be overwritten by later model refreshes without a new proposal and authorization.

#### Scenario: A proposed board is rendered

- **WHEN** a model-generated structure is shown before confirmation
- **THEN** the board and Jasper summary MUST label it proposed and MUST provide confirmation, edit, and reject controls

### Requirement: Existing surfaces remain compatible

Future implementation MUST preserve compatibility with current React Flow/XYFlow rendering, LangGraph state and handoff patterns, Agent Chat UI presentation, and PostgreSQL/session catalog routes. It MUST NOT require vector retrieval or ontology/semantic layers initially; those MAY be future adapters that preserve the canonical structured artifact and provenance.

#### Scenario: Optional memory infrastructure is absent

- **WHEN** vector or ontology infrastructure is unavailable
- **THEN** the core inquiry MUST still support structured buckets, evidence links, revisions, session persistence, and board/chat presentation through existing boundaries

### Requirement: Revision, safety, and authorization are visible

Artifact revisions MUST retain prior versions and actor/source metadata, detect or surface stale updates, and respect retention/deletion choices. The system MUST require explicit authorization for durable storage, external disclosure, cross-session reuse, and consequential actions; safety refusals MUST not be hidden by a summary.

#### Scenario: A stale update arrives

- **WHEN** a proposed update is based on an older artifact revision
- **THEN** the system MUST reject or clearly surface the conflict and MUST NOT silently overwrite a newer user-confirmed revision

### Requirement: Board and session records preserve the governance boundary

All inquiry board artifacts, summaries, playback, framework inquiries, tent poles, buckets, and decision trees MUST remain governed by the system governance layer. The system MUST NOT present generated content as empathetic, emotionally reciprocal, a human relationship, care, professional judgment, or human support. For relationship distress, anxiety, medical, legal, or financial material, artifacts MAY support bounded organization, question preparation, resource location, or healthcare/insurance logistics, but MUST NOT contain emotional, medical, legal, or financial advice, diagnosis, treatment, or decisions. Where a user appears to need human or qualified professional support, the presentation MUST neutrally encourage that support without coercion or simulated empathy.

The board and session record MUST explicitly label user-stated, sourced, inferred, proposed, and system-generated material. Silence, inaction, attention, playback, or opening/selecting a board item MUST NOT be recorded as consent, confirmation, or authorization. The governing relationship is explicit: `GOVERNANCE_FRAMEWORK.md` is a working draft, and the approved constitution, rule registry, human interrupts, and `user-intent-enforcement` intent/authorization boundary retain authority; this capability does not replace them.

#### Scenario: A sensitive inquiry is opened on the board

- **WHEN** a board contains relationship, anxiety, medical, legal, or financial material and support needs appear likely
- **THEN** the board shows only bounded organizational assistance and provenance labels, neutrally points toward human or qualified professional support, and does not simulate empathy or present advice, diagnosis, treatment, or a decision
